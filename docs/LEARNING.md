# NodeCrypt 技术全景 & 从 0 到精通学习路线

> 目标读者：**完全没有编程基础**、想以本项目为教材入门并最终能独立维护/扩展它的人。
> 学习方法：每一阶段都只学"看懂本仓库对应代码"所需的最小知识，先跑起来、再改、再懂原理。

---

## 0. 先建立全局认识（10 分钟）

本项目是一个**端到端加密的匿名聊天应用**（还带语音/视频通话）。它由三部分组成：

```
┌────────────────────────────┐
│  浏览器里的前端 (client/)   │  ← 界面、加密、通话，全在用户设备上完成
├────────────────────────────┤
│  Cloudflare Worker (worker/)│  ← 只做"邮局"：转发加密数据，看不懂内容
│  + Durable Object（房间）    │
├────────────────────────────┤
│  静态资源托管 (dist/)        │  ← 打包后的前端文件
└────────────────────────────┘
```

**产品的一句核心承诺**：服务器只搬运"漂流瓶"，永远打不开瓶盖；能开瓶的只有你和对方。

## 阶段 1：把项目跑起来（动手，不需要懂原理）

需要准备：安装 [Node.js](https://nodejs.org)（LTS 版，装完命令行里 `node -v` 能输出版本号）。

```bash
# 1. 进入项目目录
cd nodecrypt2

# 2. 安装依赖（项目用到的第三方库）
npm install

# 3. 构建前端（把 client/ 打包成 dist/）
npm run build

# 4. 本地启动完整服务（前端 + 聊天服务器）
npm run dev
```

浏览器打开 `http://127.0.0.1:8787`，开两个窗口（一个普通、一个无痕）进同一个房间，互发消息、打语音/视频——这就是你要维护的东西。

**验收**：能双窗口聊天；知道改完代码后要重新 `npm run build` 再刷新。

**概念速记**：
- `npm` = Node 的包管理器（装库、跑脚本）；
- `npm run xxx` = 执行 `package.json` 里 `scripts` 定义好的命令；
- `wrangler` = Cloudflare 的命令行工具，本地模拟云环境跑这个项目。

## 阶段 3：看懂客户端架构（这个项目是怎么组织代码的）

`client/js/` 里每个文件的职责，读代码前先背这张表：

| 文件 | 职责 |
|---|---|
| `main.js` | 总入口：初始化一切、绑定按钮、发送消息主流程 |
| `room.js` | 房间管理：加入/切换/退出房间、成员列表、未读计数 |
| `chat.js` | 聊天区渲染：气泡、系统消息、日期分隔线、输入框 |
| `ui.js` | 通用界面：登录表单、成员/房间列表、头部菜单、邀请模式 |
| `NodeCrypt.js` | **核心**：加密握手、加解密消息、收发 WebSocket |
| `util.call.js` | WebRTC 语音/视频通话管理器 |
| `util.i18n.js` | 中英文文案表（所有界面文字从这里取） |
| `util.theme.js` | 壁纸主题 |
| `util.settings.js` | 设置面板与本地偏好（localStorage） |
| `util.file.js / image.js / emoji.js / avatar.js / dom.js / string.js` | 文件传输、图片、表情、头像、DOM 小工具 |

**关键概念：**
- **状态（state）**：`room.js` 里的 `roomsData`（所有房间的数据）和 `activeRoomIndex`（当前房间）就是全应用的核心状态——界面的一切都是它的投影；
- **事件流**：WebSocket 收到消息 → `NodeCrypt.js` 解密 → 回调 `room.js` 的 `handleClientMessage` → 更新状态 → 调用 `chat.js` 渲染；
- **模块化**：一个文件一个职责，`import/export` 互相引用，改一个功能通常只动一个文件。

**动手练习**：给 `ui.start_private_chat` 这句提示改文案，并在 `util.i18n.js` 找到它的中英文定义——体会 i18n 的用法。

**验收**：不看注释，能画出"从对方按下发送到你看到气泡"的完整调用链。

## 阶段 4：网络基础——浏览器和服务器怎么说话

**最小知识：**

1. **HTTP 请求/响应**：你访问页面 = 向服务器要文件；
2. **WebSocket**：HTTP 是"问一句答一句"，WebSocket 是"一直连着的电话线"，聊天消息在这条线上双向实时流动；
3. **JSON**：`{"a":"m","t":"text","d":"你好"}` —— 数据交换的通用格式。

**对着本项目看：**
- `main.js` 里 `window.config.wsAddress` —— 客户端连哪里；
- `NodeCrypt.js` 的 `connect()`（建立连接）、`onMessage()`（收到什么做什么）、`sendMessage()`；
- `worker/index.js` 的 `handleSession()` —— 服务器端怎么接受连接、怎么转发；
- 心跳（`ping/pong`）：`startPing()` 每隔 15 秒发一次，服务器回 `pong`——这就是"在线状态"的实现。

**练习**：用浏览器 F12 → Network/WS 面板，过滤 WS 连接，观察自己发一条消息时线上跑了哪些帧（全是密文）。

**验收**：能说出"为什么网络断开后，服务器会把这个人当成退出了房间"（`seenTimeout: 60000`——60 秒没心跳就清理）。

## 阶段 5：密码学入门（本项目最难、也最核心的部分）

**先建立直觉（不需要数学）：**

| 概念 | 一句话直觉 |
|---|---|
| 哈希（sha256） | 把任意文字压成固定长度的"指纹"，不可逆 |
| 对称加密（AES） | 同一把钥匙锁/开（快，用来加密消息内容） |
| 非对称（RSA/ECDH） | 两把钥匙：公钥加密、私钥解密；或者双方各自贡献一半秘密，算出同一把"会话钥匙" |
| 端到端加密（E2E） | 钥匙只在两端设备上生成，服务器永远拿不到 |

**本项目真实的握手流程（对着 `NodeCrypt.js` 逐行看）：**

1. 客户端连上服务器，拿到服务器的 RSA 公钥（`server-key`）；
2. 双方各自生成 ECDH P-384 密钥对，交换公钥；
3. 各自用"自己的私钥 + 对方的公钥"算出**相同的** 32 字节会话密钥（`deriveBits` → `slice(8,40)`）；
4. 房间密码 `sha256` 后与派生密钥做 XOR 混合——**密码不同的人即使同房也算不出彼此密钥**；
5. 之后所有消息用这份密钥做 AES-256-CBC 加解密，逐条带随机 IV。

**动手验证**：在 `NodeCrypt.js` 里找到 `encryptClientMessage` 和 `decryptClientMessage`，把"加密后发出去的是不是和原文完全不一样"用 `console.log` 打出来看（记得完事删掉）。

**安全边界（必须理解）：** 服务器能看到"谁、什么时候、发了多大"（元数据），**看不到内容**；但"拿到邀请链接的人 = 拿到房间钥匙"，所以分享链接要谨慎（本项目已在分享时提示）。

**验收**：能对着别人讲清楚"为什么服务器没法读我的消息"。

## 阶段 6：Cloudflare Workers 与 Durable Objects（服务器侧）

**最小知识：**

- **Worker** = 跑在 Cloudflare 边缘的"函数即服务"：没有常驻进程，来请求就执行 `fetch()`；
- **Durable Object（DO）** = Worker 的"有状态房间"：一个房间一个实例，能长期持有 WebSocket 连接和内存状态——本项目的聊天室就是 `worker/index.js` 里的 `ChatRoom` 类；
- **Assets 绑定** = Worker 顺带托管静态文件（`dist/`）；
- **wrangler.toml** = 部署配置（DO 绑定、静态目录都在这里）。

**对着本项目看：**
- `worker/index.js` 的 `fetch()`：把 WebSocket 升级请求交给 DO，把其它请求交给静态资源；
- `handleSession()`：接受连接 → 生成 clientId → 发服务器公钥 → 转发加密消息；
- `handleJoinChannel()` / `broadcastMemberList()`：房间成员管理；
- `cleanupOldConnections()`：60 秒心跳超时清理。

**练习**：把 `seenTimeout` 改成 10 秒，重新 `npm run dev`，观察聊天时"一分钟不动"和"十秒不动"的在线差异。

**部署**（学完这阶段就能上线）：`npx wrangler login` → `npm run build` → `npm run deploy` → Cloudflare 控制台绑定自定义域名。

**验收**：能解释"为什么这个应用几乎不占服务器带宽，却需要 Durable Object"。

## 阶段 7：WebRTC 音视频通话（媒体不过服务器）

**最小知识：**

- **WebRTC**：浏览器内置的"点对点实时通信"能力；
- **信令（Signaling）**：打电话前要先"摇人"——SDP/ICE 协商消息；本项目的信令走房间的**端到端加密通道**（复用聊天链路，服务器看不懂）；
- **STUN**：帮你发现自己"公网上的地址"（问一下公共服务器）；
- **TURN**：P2P 打洞失败时的中转服务器（本项目目前没配，所以部分网络下通话会连不上）；
- **媒体流**：真正的声音/画面，在双方浏览器间直连，**不经过本项目服务器**，且 DTLS-SRTP 加密。

**对着本项目看**（`util.call.js`）：
- `startCallInternal()`：拿麦克风/摄像头 → 建 RTCPeerConnection → 发 offer；
- `handleOffer/acceptIncoming`：被叫方接听流程；
- `pc.ontrack`：对方媒体流到了 → 塞进 `<video>/<audio>` 标签；
- `sendSignal`：信令如何复用加密通道。

**练习**：给通话卡片加一个按钮"发送一个系统消息表示正在通话"；或把视频默认分辨率从 720p 改成 480p 看画质/流量变化。

**验收**：能说出"信令走服务器、媒体走 P2P"这句话背后的两段代码。

## 阶段 9：进阶工程能力清单（本项目已实践的案例）

这些是"精通"的体现——本项目每个点都有现成代码可对照学习：

1. **移动端适配**：`phone.css` + `visualViewport` 键盘处理（软键盘不遮挡输入框）；
2. **暗色模式**：CSS 变量 `--nc-*` + `[data-theme="dark"]` + 跟随系统；
3. **国际化 i18n**：文案与代码分离，中英一键切换；
4. **可访问性**：键盘操作（tabindex/Enter/Esc）、ARIA 标签；
5. **性能**：长会话气泡上限渲染（虚拟列表的简化版）、成员数增量更新；
6. **安全设计**：TOFU 服务器密钥警示、邀请链接"钥匙"语义、元数据最小化；
7. **优雅降级**：摄像头不可用自动降级纯语音；
8. **产品直觉**：已读回执"对方真的在看才算已读"的交互定义。
